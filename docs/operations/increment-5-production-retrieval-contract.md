## Authority and non-effects

SQLite, immutable decisions and governed objects remain authority. Neo4j,
full-text and vector structures are disposable projections. Retrieval returns
context only.

Increment 5 authorises no live source, provider/model call, production
embedding, external egress, credential, spending, evidence acquisition,
publication, live shadow, canary or production activation. It creates no Event
Hypothesis or Candidate authority.

## Profiles

`FIXTURE_REPLAY` is hermetic and zero-call. It is useful for deterministic
component evidence but is not production qualification.

`PRODUCTION_SHAPED_QUALIFICATION` may use affected authenticated repository
services such as Neo4j and approved full-text/index infrastructure. It still has:

- zero provider/model call and zero provider spend;
- no live source or protected expression;
- no graph write or publication authority;
- no public effect; and
- no activation effect.

A profile cannot widen fixed contract limits, treat a fixture vector as a
production embedding, or replace a mandatory branch with a fake passing mode.

## Validator identity

The canonical profile validator is executed only through the signed outer
workflow from its exact reviewed Git blob. The launcher binds:

- exact commit and tree;
- exact validator blob;
- root-owned system Python and no-site execution;
- canonical manifest bytes;
- inner receipt digest;
- Evaluation Epoch identity; and
- the complete launcher command and environment contract.

The standard-library-only inner validator imports no repository module or
environment package. It verifies the explicit Git directory, work tree and
index; disables replacement objects and fsmonitor; rejects
assume-unchanged/skip-worktree flags; and reads only digest-pinned blobs from
the exact commit.

The inner receipt truthfully records
`executed_source_identity_attested=false`,
`validation_code_identity_claim_effect=NONE` and
`outer_signed_workflow_binding_required=true`. It is necessary evidence only.
It cannot authorise qualification or activation.

Mutable checkout cleanliness is a bounded pre-receipt snapshot, not a
completion-time lock. The signed outer evidence relies on immutable commit,
tree, validator-blob, manifest and receipt identities.

## Epoch

Every qualification run binds a frozen Epoch before execution. The Epoch
covers exact:

- contract and Plan;
- component, source, provider, adapter and parser versions;
- query, threshold and policy sets;
- dataset manifest and deterministic labels;
- code tree; and
- selected projection generation.

A changed frozen identity starts a new Epoch. A missing or mismatched identity
is `NOT_EVALUATED`. Runs from materially different Epochs are not pooled.
Failed, inconclusive and superseded outcomes remain retained.

## Hard request limits

Unless a more restrictive accepted profile applies, the bounded retrieval
contract uses:

- 5,000 ms end-to-end timeout;
- eight results per branch;
- twelve retained fused candidates;
- 262,144 response bytes;
- zero external provider calls and zero provider cost;
- graph depth two and fan-out 32; and
- a 31-day graph temporal window.

Limits are never silently widened.

## Request outcomes

- `COMPLETE` — all mandatory request-local authority, branch, hydration,
  freshness and collision checks completed.
- `DEGRADED` — only an explicitly optional contribution failed and bounded
  meaning remains.
- `INCOMPLETE` — required authority, branch, collision or request-local
  evidence is missing.
- `POLICY_BLOCKED` — rights, scope or security forbids the material.
- `STALE` — selected authority, generation or watermark is outside the admitted
  boundary.
- `UNAVAILABLE` — no safe bounded response can be produced.

An empty result is no-match only with `COMPLETE`. A request outcome does not
itself create a Hypothesis/Candidate, select Watch/Hold, continue source
collection or complete later reconciliation.

## Named-surface security

Only bounded named tools expose retrieval. The surface rejects:

- raw or generated Cypher;
- graph writes;
- caller-selected indexes or predicates;
- caller Lucene syntax;
- unrestricted source text;
- model/provider or publication credentials;
- secret-bearing output;
- scope, caller or purpose confusion; and
- projection text presented as factual authority without hydration.

Untrusted source, result or model content is data and cannot alter tool
authority, policy, egress, budgets or credentials.

## Rights and purge

Rights are checked at read and hydration time. Withdrawal stops derivative
creation. Purge removes affected passages, full-text entries, vector
derivatives, graph derivatives and retained contexts; records exact derivative
identities and a purge receipt; rebuilds an isolated generation; and proves
non-resurrection before selection.

A residual prohibited derivative blocks the affected scope.

## Projection loss and recovery

Graph or index absence, lag, gap, dead letter, incompatible contract, tamper or
stale generation remains explicit and cannot become no-match.

Retrieval-specific recovery:

1. detects the affected projection;
2. isolates it from serving;
3. rebuilds from retained authority without stochastic historical rewrite;
4. verifies contract, generation, watermark, gaps, rights and digests;
5. selects only the qualified replacement; and
6. retains prior failure and recovery evidence.

This is not complete-newsroom backup/restore or post-restore operational
reconciliation; those remain #148.

## Gate application

- Tier L applies to a leaf retriever or equivalent bounded component.
- Tier S applies to Neo4j, authority-read, rights-sensitive hydration or
  cross-component integration.
- Tier M applies once at #251, #252, #253 and final #254 closeout.

The final Increment 5 proof uses one exact integrated `main` head, all
applicable permanent workflows, affected authenticated services, signed SDLC,
retrieval-specific replay/rights/failure evidence, clean substantive review and
zero unresolved P1/P2 findings or review threads.

## Explicit exclusions

Increment 5 does not deliver:

- Event Hypothesis or Candidate integration;
- downstream collision enforcement or Handoff completion;
- prospective event universes or production human labels;
- reviewers, blinding, adjudication or release-evidence authority;
- Operational Profiles, schedules, queues, leases, retries or capacity;
- full health/coverage posture, incidents, runbooks or manual actions;
- complete-newsroom backup/restore or reconciliation;
- intended-hardware cost/licence admission;
- live shadow, canary, publication or production activation.

Those exclusions are ownership transfers, not waived requirements.
